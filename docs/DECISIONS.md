## 业务修正（来自开发计划 v1.1）

1. 招募截止与活动生命周期分开：截止停止申请和批准，至少两位有效成员的队伍可保持待开始；不足两人过期。仅在计划开始至结束之间由队长开始。未开始且超过结束时间过期。
2. 总人数包含队长，待审核不占位。FULL 不接收新申请，保留旧待审核；真正关闭时让剩余申请失效并通知。
3. 当次场景回答和时间确认独立保存；自述资料不显示为已认证。
4. 队伍变更共用事务锁；站内通知与状态同事务落库；提交后再推送。
5. 硬条件 PASS / FAIL / UNKNOWN 优先，信息不完整不展示误导性的总匹配百分比。
6. 退出、移除、封禁、注销同步撤销已有 HTTP 与 Socket 权限。
7. AI 仅产生用户确认的草稿和受约束解释，失败保留输入并允许手填。
8. 删除队长账号先转交或取消；浏览学校与自述学校身份分开校验。

各模块开始时把对应修正落实到迁移、契约与测试；未实现项不记为完成。
