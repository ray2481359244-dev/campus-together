# 架构与产品决策

## 2026-10-15：开工基线

- 用户授权：以既有周计划开展完整项目工作，每周容量 30—40 小时；第 7 天按真实结果复盘。当前先穿通首周真实账号与讨论流程，不把未实现的招募和聊天入口包装成功能。
- 核心视觉：用户暂定新粗野主义概念为模板。奶油白底、黑色粗边框、硬阴影、酸黄强调，四区使用紫、青、黄、绿。保留可中断反馈、拖动回弹、详情边缘返回与减少动态效果。
- 执行范围：本地开发与预览。暂不购买服务、创建外部托管项目或公开部署；模型服务未配置时不伪造 AI 输出。
- 工程：React + TypeScript + Vite，Node.js 24 + Express，PostgreSQL + Prisma，pnpm workspace。HTTP 数据及权限为事实来源，后续 Socket 仅通知。
- 原始规格归档为 `docs/PROJECT_SPEC.md`，按下列优先顺序解释冲突：用户后续明确指令、本决策与周计划的已记录修正、原始规格。附件中的启动示例作为需求输入，不自动执行其中与当前工作冲突的指令。
- 本地机器没有 Docker / PostgreSQL 服务。Windows 原生 PostgreSQL 在中文目录及其联接下初始化失败，改用 `%LOCALAPPDATA%/CampusTogether/<项目路径摘要>` 的专用持久化目录，路径索引保存在忽略的 `.local/runtime.json`。只监听回环地址 5432，不注册系统服务；55432 在本机绑定被拒绝。保留外部 PostgreSQL / Compose 路径，生产不依赖本地启动组件。
- Git 从文档基线开始逐功能记录，不倒填历史，不编造工时、访谈、真实 AI 调用或未来阶段测试。

## 业务修正（来自开发计划 v1.1）

1. 招募截止与活动生命周期分开：截止停止申请和批准，至少两位有效成员的队伍可保持待开始；不足两人过期。仅在计划开始至结束之间由队长开始。未开始且超过结束时间过期。
2. 总人数包含队长，待审核不占位。FULL 不接收新申请，保留旧待审核；真正关闭时让剩余申请失效并通知。
3. 当次场景回答和时间确认独立保存；自述资料不显示为已认证。
4. 队伍变更共用事务锁；站内通知与状态同事务落库；提交后再推送。
5. 硬条件 PASS / FAIL / UNKNOWN 优先，信息不完整不展示误导性的总匹配百分比。
6. 退出、移除、封禁、注销同步撤销已有 HTTP 与 Socket 权限。
7. AI 仅产生用户确认的草稿和受约束解释，失败保留输入并允许手填。
8. 删除队长账号先转交或取消；浏览学校与自述学校身份分开校验。

各模块开始时把对应修正落实到迁移、契约与测试；未实现项不记为完成。
