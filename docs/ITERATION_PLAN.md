# 动态迭代计划

2026-10-21 起生效，最新更新 2026-10-26。每次工作结束先总结，再按结果制定下一次计划。此文件是当前执行入口；原周计划保留目标、规则和候选任务，原日期 / 工时分配不再作为固定执行顺序。

## 每轮怎样推进

1. 开始时核对代码、上轮结果和最新反馈，选择一个主要用户结果；只细化本轮，后续保留候选。
2. 开发时把必要的契约、数据、API、界面和权限一起落实。遇到阻断先处理，提前完成可继续同一流程的下一小步，不等日历日期。
3. 按影响做必要验证：代码变更检查相关风险，重要集成节点做完整回归；纯文档检查事实、链接与差异，不重复跑业务测试。
4. 结束时简要记录完成、验证、未完成及原因，再按实际内容提交并自动上传 Git。失败或未验收的部分如实保留。
5. 基于实际结果重排下一轮，并说明为什么优先做它。用户反馈随时调整排序；阶段性总结按完成的业务里程碑进行，不强制每七天重排。

每轮汇报固定包含：本轮交付、验证结果、遗留问题、下一轮目标。详细事实追加当天日志；只有规则、接口或架构变化才同步对应文档，避免反复改写同一段进度。

后续收到“继续”时，依据最新代码、反馈和本入口推进下一轮，不必重新从完整计划书排期。
