# 碰个头：奇思妙想界面实装

把已确认的封面与圆桌方案接入现有 React 应用，保持真实业务和 API 契约。按以下顺序组织变更与提交：

1. **视觉基础与原创资产**：修正肢体的圆桌插画、四种云形、角色图集、授权字体、可取消云转场、动效偏好及可释放的交互式背景。
2. **入口与账号流程**：封面、碰撞标题、独立账号布局、共享学校上下文、真实登录注册及平台会话边界。
3. **整屏发现与云分区**：可深链的 home / interests / discussion、云铺展、真实讨论查询与浏览返回状态。
4. **全站视觉与交互回归**：平台壳、招募、发布、消息、个人、收藏、详情及管理页面统一皮肤；真实点赞收藏的反馈与失败处理，响应式、键盘、动效和完整功能验证。

## 视觉原则

纸面 `#fff9ef`，墨色 `#343039`，主色 `#f5ff72`；四区分别为紫 `#ddd0ff`、蓝 `#cfe8fb`、淡黄 `#fbefac`、绿 `#d9edc5`。站酷快乐体用于标题和手写式注释，正文采用系统中文无衬线字体。

圆桌人物由原创 SVG 生成，身体和桌前手臂共享髋部坐标、姿态与动画帧；角色插画保持童趣的头身比例和自然关节。交互在用户操作时回应，背景空闲暂停；系统减少动态效果和手动动效开关均有效。

## 源资产与维护

- `scripts/design-assets/` 保存人物、表情、坐姿、桌面遮挡和云形的原创源文件。
- `node scripts/generate-visual-assets.mjs` 同步圆桌 React 插画、分区映射与角色 SVG 图集。
- `apps/web/src/components/visual/assets/OFL.txt` 保存字体许可证；字体随应用构建提供，无外部字体服务依赖。
- 概念稿内的假登录、内存数据、iframe 和模拟请求不进入正式应用。

## 业务边界

保留 AuthProvider 的会话恢复、CSRF、跨标签账号变化与缓存清理；保留真实学校列表、分页 query key、幂等请求与权限处理。云动画只负责视觉覆盖，页面状态在覆盖后提交；切页不能替代服务端状态、吞掉错误或重复业务请求。
