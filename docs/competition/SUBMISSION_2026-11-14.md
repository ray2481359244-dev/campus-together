# 碰个头 / CampusTogether 参赛说明

2026-11-14 · 全国高校 Vibe Coding 开发挑战赛作品材料

## 作品

同学可以在游戏、学习、竞赛和户外四个区找到话题，先交流，再决定是否参加活动。帖子作者或读者能从合适的话题发起招募；队长按场景决定加入方式。想先聊几句，可以从评论发起联系；正式加入后，队伍群出现在「消息」里。

| 评委可操作的路径 | 本版在哪里查看 |
| --- | --- |
| 找同好、回帖子 | 发现 → 选择四区之一 → 帖子正文 / 评论 / 相关招募 |
| 发轻量招募、选择加入方式 | 发布 → 招募；时间可约定或待商量，按场景展开条件 |
| 查看申请依据与正式名额 | 招募详情 → 核对条件并提交；队长在「消息 → 通知 → 待处理」决定 |
| 评论后发起私聊，或从帖子进讨论群 | 评论旁「私聊」；评论区的「帖子讨论群」 |
| 收发、设置与管理 | 消息 → 全部 / 私聊 / 我的队伍 → 会话；群资料含成员、公告、审核和管理 |
| 成员权限与活动结束 | 非成员访问同一聊天入口会被拒绝。结束后成员可在归档期内只读查看 |

统一列表支持置顶、免打扰、未读摘要、会话草稿、回复引用、@ 与图片、本会话记录搜索。界面保留各板块配色与全局动效开关，遵循系统减少动效偏好。外部同学试用、真机软键盘及干净电脑首次安装时间按[实测表](REHEARSAL_AND_TRIAL.md)记录。

## 评审复现

安装 Node.js 24 LTS、pnpm 11.5.1 后，在源码根目录运行：

```powershell
pnpm.cmd install --frozen-lockfile
pnpm.cmd demo
```

打开 `http://127.0.0.1:3180/discover`。启动器准备独立 PostgreSQL 数据库、执行迁移、构建并导入标记为虚构的四区内容。使用小河（队长）、小林（报名者）、小梅（非成员）和管理员四个独立浏览器会话。账号、重复演练、端口占用与停止方法见 [本地演示操作说明](LOCAL_DEMO.md)。本机复现已验证，10 分钟异机首装待实际计时。

## 架构与演进

- React、Vite、TypeScript 完成界面，Express 提供服务 API，Prisma 与 PostgreSQL 承载真实数据。共享契约位于 `packages/contracts`。`pnpm-lock.yaml`、迁移、演示数据生成器和自动化测试随源码交付。
- 申请提交与批准分开。批准事务重新检查条件、有效成员、总人数和分工余量，并写入审核结果和通知；待审核不占名额。帖子讨论群使用独立成员身份，队伍群按正式成员资格授权。
- 消息先写入数据库。客户端请求 ID 支持结果未知时重试，避免生成第二条消息。SSE 发更新信号，正文和图片经身份校验后读取，断线后使用 HTTP 回填；群归档延续 30 天读取窗口。
- 两项增量迁移位于 `202611120001_social_conversations` 和 `202611120002_flexible_recruitment_schedule`。旧招募与队伍引用仍可读取；允许无固定起止时间的轻量招募后，数据库和服务端校验同步按实际状态处理。
- 作品从校园协作方案逐步搭建，使用通用依赖及已随项目保留许可的字体。开发采用 AI 协同。应用内「条件辅助」以规则输出依据，当前演示使用规则模式，完整运行不需要模型密钥。

## 验证与过程材料

`pnpm check` 核对共享类型、数据库集成与构建。浏览器测试用 `pnpm test:e2e`，按社区界面、账号、队伍流程分组，共享业务限流仍生效。独立演练 `pnpm test:demo-flow` 检查申请、审批、群聊、直接加入、非成员与管理员读取拒绝、结束只读以及重启后的数据持久化。

本机前后端类型检查、构建与 181 项服务端集成均通过。社区界面组 19 项、账号组 12 项通过，队伍流程 13 项在整组回归和针对受影响用例的复跑中逐项通过。11 月 13 日四账号独立演练确认重启后历史消息和队伍归档保留。

新版消息设置引入额外的异步状态。回归把保存成功断言限定到相关提示；账号过期用真实服务端撤销，在待提交的资料请求放行前完成。审核结果用招募标题、通知类型和具体申请 ID 定位，再验证一次投递、跨账号读取拒绝和已读持久化。举报流程断言已同步到当前提交回执文案。
