# CampusTogether UI设计语言规范

版本：v1.1　日期：2026年10月15日　适用范围：参赛版响应式Web

**界面采用明亮、清新的iOS式层级与分组，加入能即时响应手指的交互。** 薄荷浅底、白色内容表面、天空蓝主操作和柔和主题色形成校园氛围。设计语言沿用Campus UI，本次修订为清新版。

本次按用户反馈固定明亮浅色，概念稿不随宿主深色外观自动变暗。暗色仅保留为以后显式启用的候选，不是当前默认模式。具体色值、尺寸和动效参数是本项目设计决定，不是Apple官方规定。

## 设计原则

- **先看懂。** 用户无需猜测图标；主要动作有文字，人数、时间、岗位和状态直接显示。
- **少分心。** 中性色背景和稳定分组承载主要信息，主色集中在操作与选中态。
- **有秩序。** 同类内容保持相同位置、单位、格式与对齐方式，招募卡片便于横向比较。
- **反馈明确。** 操作有加载、成功、失败和重试结果；申请中与已入队严格区分。
- **轻松友好。** 通过四区图标、柔和辅助色和简短文案表达校园氛围。

借鉴Apple关于视觉层级和材质对比的设计思路；Web实现仍以实际浏览器、可访问性和性能为准。[Apple布局](https://developer.apple.com/design/human-interface-guidelines/layout)、[Apple材质](https://developer.apple.com/design/human-interface-guidelines/materials)

| 蓝色浅底 | #E7F4FF | 当前导航、条件区域轻强调 |
| 分隔线 | #D7E9E7 | 辅助划分；不能作为唯一控件识别手段 |

主要蓝色按钮配白字计算对比度约4.55:1；次要文字对页面底色约5.41:1；文字操作蓝对蓝色浅底约5.29:1；三类状态文字对各自浅底均超过4.5:1。该结果仅覆盖指定静态配色，不等于完整页面通过可访问性验收。普通文字目标至少4.5:1，较大文字目标至少3:1；真实透明背景和所有交互态仍需检查。[WCAG文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

四区辅助色采用游戏紫#754BC4、学习青#087E72、竞赛橙#A65B00、户外绿#287D4B，对应底色为浅丁香#F3EDFF、浅薄荷#E1F9F0、浅杏#FFF2D9和浅芽绿#EAF8E5。辅助色用于小图标底、主题标签和局部识别，整张卡片保持明亮。品牌小标记可使用薄荷到浅蓝的轻渐变，不用于正文或大面积背景。标签始终带名称，状态不能仅靠颜色表达。

## 字体和阅读

字体采用系统字体栈：system-ui、-apple-system、BlinkMacSystemFont、Segoe UI、PingFang SC、Microsoft YaHei、sans-serif。Apple设备使用系统提供的字体，Windows保持自然的中文显示；不依赖额外字体下载。

| 层级 | 移动端 | 桌面端 | 使用规则 |
| --- | --- | --- | --- |
| 页面标题 | 28px / 600 | 32px / 600 | 每页一个主要标题 |
| 区域标题 | 20px / 600 | 24px / 600 | 少量明确分组 |
| 卡片标题 | 18px / 600 | 18px / 600 | 允许自然换行，不为对齐而裁掉必要条件 |
| 正文与表单输入 | 16px / 400 | 16px / 400 | 中文行高约1.5—1.65 |
| 按钮与标签 | 14—16px / 500 | 14—16px / 500 | 主操作至少16px |
| 辅助元信息 | 13px / 400 | 13px / 400 | 只承载次要信息，必要时换行 |

核心信息不缩小到12px以下。字号随用户缩放可增长，200%缩放下检查操作和阅读。数字名额可使用等宽数字特性；正文不使用细到难辨认的字重。

## 间距和形状

采用4px基础步长，常用间距8、12、16、20、24、32、40。手机页面左右16px，普通卡片内边距20px；窄屏可降到16px。相关字段间12—16px，分组间24—32px。

普通卡片圆角20px，输入与按钮12px，小标签8px，分段切换容器16px；头像与简短状态可使用圆形或胶囊。卡片边界和阴影采用淡蓝绿，选中卡片用轻边界和柔和抬升表达，避免硬蓝色描边。阴影保持克制。

内容表面保持实色。半透明和轻模糊最多用于少量导航浮层，提供不透明回退；关键条件、正文、按钮文字不叠在复杂背景上。首周先采用实色导航，效果增强不得影响阅读和低端设备操作。

## 布局与导航

| 尺寸 | 布局 |
| --- | --- |
| 小于768px | 单列内容，底部发现、招募、发布、消息、我的；详情主要操作保持容易触达 |
| 768至1199px | 左侧精简导航与主内容；详情可独立打开，减少拥挤 |
| 1200px及以上 | 左侧导航、中间主要列表、右侧条件或队伍摘要；总体内容宽度适度限制 |

发现和招募共享四区切换，区域切换保留各自合理状态。主导航不随页面随机改名。图标配文字，发布入口不以纯图形暗示。返回后保留必要筛选和列表位置。

招募使用单列卡片；讨论优先单列易读布局，较宽视口再评估双列。桌面端通过信息分区提高效率，手机端控制单屏信息密度。

## 组件规则

| 组件 | 规定 |
| --- | --- |
| 主按钮 | 蓝底白字，一个操作区域保持一个最高强调动作；文字具体，如发布招募、申请加入、批准申请 |
| 次按钮 | 中性或蓝色轻底；与主按钮有明确层级 |
| 危险操作 | 红色文字与明确名称，执行取消队伍、移除等不可轻易恢复的动作前说明具体影响 |
| 输入框 | 可见标签，示例不能代替标签；错误贴近字段并保留已输入内容 |
| 分段切换 | 白色滑块随点击、键盘或水平拖动移动；拖动时跟随手指，松手后轻弹吸附，提交最终选择；垂直滚动不被抢占 |
| 招募卡片 | 固定信息顺序：区域与主题、标题、时间、地点、名额或岗位、状态和主要入口 |
| 条件对照 | 符合、冲突、待确认使用图标加文字；依据可展开，未知不显示为通过 |
| 群聊 | 发言者、时间、发送中或失败状态清晰；队伍状态与成员入口容易找到 |
| 弹层 | 标题、影响、确认和取消明确；支持键盘关闭、焦点管理，关闭后恢复触发位置 |
| 站内通知 | 内容摘要足够判断事情，点击后进入对应对象；不复制私人聊天全文 |

主要触控区域至少44×44 CSS像素。图标可小于触控区，但点击区域不能只剩图标本身。键盘焦点可见，不能只用悬停显示必要动作。

## 趣味性的边界

四区图标统一使用同一套线性图标，可分别选择游戏手柄、书本、奖杯和树叶。线宽、尺寸和视觉重量统一。头像、主题图和活动封面允许表达个性，但不依赖真人照片制造可信感。

可以采用轻微的按压反馈、状态变更后的勾选出现，以及简短的成功文案，例如“申请已发出，等队长确认”。空社区可写“还没有相关讨论，来聊聊你的想法”。

趣味不增加强制积分、抽奖、签到或长动画；成功反馈不遮挡下一步。队伍成立时可有一次简短反馈，但应尊重减少动态效果设置。

## 动效

交互先响应输入，再完成过渡。按钮按下约150ms内出现轻微缩放反馈；内容切换约220ms，详情进入约280ms，草稿展开约260ms。拖动中的位置直接跟随指针，不能先等待一段动画。松手吸附使用轻阻尼弹簧，概念稿参数为刚度480、阻尼34，后续按实机体验调整。

四区滑块可以点击和拖动，键盘支持左右方向键、Home和End。滑块跟随拖动，但列表只在松手确认后切换，避免快速滑过时不断重新生成内容。新的选择可以打断上一段过渡，不能排队播放旧动画。

手机详情支持左侧边缘向右拖动返回。拖动距离跟随手指，达到距离或速度门槛后返回，未达到时回弹；取消手势同样正确复位。页面中的垂直滚动、复选框和表单输入保持正常操作。拖动期间背景列表只是过渡预览，不授予任何新业务权限。

状态变化采用短促反馈，页面切换组合小幅位移与透明度；鼠标悬停可轻抬卡片，触屏不依赖悬停。列表不逐卡延迟登场，不做持续漂浮和闪烁。首屏不播放无意义的入场动画。

使用prefers-reduced-motion关闭额外弹性和位移动画，直接拖动和按钮仍可操作。动画尽量使用transform和opacity；表单展开仅对局部内容短暂调整高度。后续实机验证流畅度、连续点击和取消手势，不能仅因桌面预览顺滑就声称手机达到某个帧率。[WebKit动态效果适配](https://webkit.org/blog/7551/responsive-design-for-motion/)

AI状态显示实际阶段，例如正在生成草稿、正在校验、需要你确认、生成失败。不能伪造内部思考、不断增长的假进度或模型已经成功的结果。网络失败时保留输入，并显示重试和继续手填。

## 每页状态必须齐全

加载中显示合理的内容骨架或明确提示；空数据说明下一步；失败有重试入口；无权限解释需要登录或成员资格；提交中避免重复操作；成功结果明确对象与下一步。表单草稿和凭据分开处理。

申请中不能展示群聊入口为已授权，已结束和已满员不能继续显示可加入操作。资料未知要标为待确认，不使用虚假的高适配百分比。

## 首周UI验收

1. 用同一套变量完成导航、按钮、输入、卡片、状态与弹层，不在每页另造样式。
2. 检查320、390、768、1440px视口；200%缩放检查必要内容，表单在手机软键盘出现时仍可使用。
3. 普通文字、链接、按钮文字和状态标签符合目标对比度；输入边界和焦点可识别。
4. 键盘可以到达和操作主要控件；弹层不丢失焦点；图标按钮有名称。
5. 加载、空态、失败、无权限和提交结果均有对应设计。
6. 动效不阻塞操作；连续快速切换没有旧状态回放；拖动、取消和松手能正确收敛；减少动态效果时核心流程仍完整。
7. 示例数据明确标注，视觉评审不计为功能验收。
8. 宿主使用深色外观时，本次清新版仍保持浅色；核心文字和状态不因提亮而失去对比度。

## 变更方式

先修改语义变量或共享组件，再检查使用页面；局部特殊样式必须有理由。首周复盘固定基础语言，后续按真实用户反馈修正可读性和效率，避免每周更换整体视觉风格。
