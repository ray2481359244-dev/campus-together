## 真实发现与实现

| 问题或边界 | 本轮处理 |
| --- | --- |
| 成功响应丢失后重试产生两帖 | 旧构建通过真实 HTTP 保存后主动丢弃响应，再次点击发布，列表实际得到两帖，断言期望 1 / 实际 2；失败 trace 与截图保存在忽略的 `.local/evidence/2026-10-19-before/` |
| 并发重试不能仅靠禁用按钮 | POST 必填 UUID requestKey，Post 新增作者范围唯一标识与规范化内容 SHA-256；事务内 createMany / skipDuplicates 与读取协调并发，首次 201、重复 200 |
| 相同标识却修改正文 | 返回 409 REQUEST_KEY_CONFLICT，不覆盖原帖；创建重试也不覆盖后来正常编辑的版本 |
| 原帖已经删除或隐藏 | 保留标识占位，重试 410 POST_UNAVAILABLE，不返回正文，不重建 |
| 学校资料或主题在发布后变化 | 优先解析已经成功的请求，返回原帖当前可见版本；不迁移学校，不要求停用主题重新可用 |
| 发布结果未知时继续修改输入 | 固定本次内容并锁定字段，显示“核对并完成发布”；成功后进入详情再编辑，明确主题校验拒绝则解锁 |
| 网关 400 不能证明未落库 | 只有明确的 INVALID_INPUT / TOPIC_UNAVAILABLE / PROFILE_INCOMPLETE 才解除固定提交；非 JSON 400、503、限流和超时保留同次标识 |
| 旧数据与客户端兼容 | 增量迁移仅新增两个可空字段和唯一索引，旧帖不补造标识；新接口缺少 requestKey 返回 400，旧页面须重新载入 |

没有通用全站幂等缓存，也没有跨整页刷新或关闭页面的自动备份。创建与编辑分别使用请求标识和 revision；账号切换沿用旧缓存 / 表单清除规则。接口、规格修正和决策已随代码提交同步。

## 失败与修正过程

1. 沙箱内 pnpm 曾因项目路径 realpath 权限失败，沙箱内端口探测也不能确认运行状态；正常本机权限下诊断为 STOPPED。没有据此改项目依赖或结束未知进程。
2. 旧构建的目标复现 1.8 秒内失败：期望只有 1 帖，实际 2 帖。这是产品缺陷，原始失败产物在后续测试前另存，没有把失败记成通过。
3. 第一轮数据库 40 / 42，两项返回 429：新增检查在同一 IP 累计超过每分钟 40 次写入。独立用例只重置测试自己的限流桶，产品限制不变；下一轮 42 / 42 通过。
4. 首次完整浏览器使用 23 个测试，20 通过、3 失败：恢复页按精确名称查找区域选择器没有匹配；两个较晚注册被累计登录限流挡住。为选择器补明确无障碍名称，将同一发布体验的三个分支合并为同一账号连续步骤；既有断言保留，没有提高产品配额。随后 21 / 21，42.6 秒通过。
5. 整页截图初次仍在滚动位置，固定跳转入口在合成截图中偏移；回页首后重新截图并检查，没有为截图改变产品样式。聚焦恢复流程单独通过 1 / 1，5.6 秒。
6. 自检收紧错误分类：网关非 JSON 400 不是明确业务拒绝，不能放开内容并生成新标识。新增这一分支后再次类型 / 构建通过，最终完整浏览器 21 / 21，42.3 秒。
