## 发现的问题与修复

| 问题 | 原行为 | 现在的行为与验证 |
| --- | --- | --- |
| 后台重新读取覆盖未保存输入 | 编辑表单随查询 data 变化调用 reset；另一标签页更新后，本地标题被服务器新标题替换 | 表单只在首次载入或明确确认时初始化。真实双标签页与后台刷新验证本地输入保留 |
| 静默更换提交 revision | 保存直接使用查询缓存里的最新 revision；即使本地文稿基于旧版，也可能提交新版本号 | 编辑基准内容与 revision 一起固定。旧稿提交得到 409，输入不丢失，也不会自动变成基于新版的写入 |
| 冲突后只有报错，恢复选择不清楚 | 泛化提示重新载入；容易直接刷新页面丢稿 | 可“核对已保存版本”，阅读服务器标题 / 正文 / 时间 / 版本；“用此版本重新编辑”须再次确认，可取消并继续保留输入。没有自动合并 |
| 读取失败可能用整页错误替换表单 | 已有编辑内容时，后台读取失败也进入整页错误分支 | 初始加载失败仍有重试；已开始编辑后，失败提示内联显示，本地标题和正文仍在。原文已删除的 404 亦不清空输入 |
| 保存响应与写入分开读取 | 条件更新后，事务外另查帖子；中间可能已有后续写入 | 条件更新与响应快照读取放入同一事务，读取前保持该行更新锁；不扩大到全局锁 |
| 保存时仍可继续改输入 | 提交期间可能产生未包含在请求中的文字 | 请求期间禁用当前字段；新建与编辑路由使用不同 key，避免旧编辑状态带入新建表单 |

新建讨论目前没有请求幂等键。连接中断可能发生在成功落库之后，不能仅凭错误断言未发布；界面现在提醒先回讨论板核对，避免重复发布。本轮未把招募已有的幂等能力冒称为帖子已有能力。

## 真实失败与修正过程

1. 最初两次浏览器复现均超时 45 秒，卡在等待背景读取。第一版没有使目标页回到前台，且事件发送给 document。检查本机已安装查询库源码后确认监听位于 window；修正为先 bringToFront、虚拟时钟推进 21 秒，再给 window 发送可见性事件。两次超时属于测试步骤问题，不计为产品缺陷已复现。
2. 在旧构建上再次执行，9.8 秒内实际触发 GET 200，断言失败：期望“当前标签页尚未保存的想法不能丢失”，实际变成“另一个标签页已经保存的新标题”。这次才是目标缺陷的真实失败证据。旧 trace / 截图留在忽略的本地产物，不上传私人会话。
3. 构建修复后运行完整浏览器回归，新增流程通过：旧稿提交 409；核对、取消、明确载入新版；保存 503 保留输入后重试成功；原帖删除后核对 404 仍保留正文；转去新建页字段为空。
4. 两项真实数据库并发测试分别检查同版本双编辑只有一个成功，以及编辑与删除竞争不会复活已删除讨论。失败方不覆盖成功方，响应正文和 revision 与成功请求一致。
