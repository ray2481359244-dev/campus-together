## 截图反馈修复：人物图层与云朵消息

负责人提供五张正式项目截图，指出圆桌人物脸部被轮廓线遮挡、招募折叠入口动画完成后字体突然缩小，并要求单帖提醒铃铛，以及评论 / 聊天 / 通知采用逐朵弹出的云朵反馈。本轮直接修复正式项目，保持已确认的纸色、人物和工作台主题。

### 原因与实现

- 圆桌 `conversation-marks` 装饰线位于人物之上，其中几段跨过粉色、蓝色和绿色角色脸部。将整组装饰线移到所有人物后面，并由 `scripts/design-assets/seated-scene.mjs` 重新生成正式 React / SVG 两份资源；没有对截图打补丁或改变表情五官。
- 全局按压的 80ms 动画使用 forwards fill，但完成时提前从跟踪表删除。长按超过 80ms 后，释放动作无法取消残留的 `.955` 缩放；回弹结束就再次露出较小状态。现在保留按压引用至释放 / 取消 / 失焦，从实际当前比例衔接回弹，最后回到原始尺寸且没有残留填充动画。压感幅度调整为 `.975 → 1.025 → .996 → 1`。
- 草稿 / 本人招募 / 岗位申请改为共享 `SoftDisclosure`，保留原生 details / summary 与键盘语义。仅面板高度做 280ms 连续过渡，不缩放整块文字；快速反向操作从当前高度接续，关闭动效立即落位。
- 帖内和消息中心共用 `BellFeedback`。真实开关请求成功才增加播放序号：铃铛摇动、关闭斜线逐笔绘制 / 开启时擦除、浅紫光圈散开。失败保留原态，刷新 / 缓存更新 / 重新开启动效不重播成功动画。
- 评论、群聊、通知列表与站内提醒共用 `useCloudArrival`。初次历史建立基线，未见过的新记录从下方抬起，纵向压缩后回弹，540ms 落位；同批逐条错开 60ms，最大延迟 240ms。已知 ID 的轮询、已读变化、内容编辑不重播；较早群聊历史和删除事件不播放新消息效果。评论与消息气泡采用同主题云角与小尾巴。
- 合并点赞通知沿用已有通知 ID。提示弹窗使用 ID + 服务端更新时间识别新版本，使不同人的后续点赞仍有新反馈，普通重复读取保持安静。通知卡片本身不因计数更新整体重播。

动效在手动关闭、系统减少动态效果或卸载时取消，不用假消息、假成功或延迟发送来制造动画。没有新依赖、后端改动、迁移或主库 / 演示库清理。
