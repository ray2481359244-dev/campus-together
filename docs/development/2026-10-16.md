## 1 本地运行与启动改进

新增 `pnpm doctor` / `node scripts/doctor.mjs`。只读检查 Node、依赖、环境、端口、API 标识、前端代理和数据库 readiness，不打印密钥、不删数据、不自动结束占用端口的程序。

开发服务提供当前工作区的短摘要标识，仅在非生产且显式设置时返回，避免把其他检出目录或无关程序误认为当前项目。API 的完整磁盘路径不公开。

`pnpm local` 在服务已就绪时直接给出地址并正常退出，不重复执行数据库和迁移；有端口冲突、残留半套服务或配置问题时清楚提示。外部数据库由其负责人管理，启动链跳过本地 PostgreSQL 辅助程序。

Windows 根目录新增 `启动平台.cmd`，检查 Node 24、提示缺失依赖，保留终端以便看错误和持续预览。批处理使用 CRLF，Git 属性固定行尾；不是自动后台常驻或开机启动。

执行中真实发现并处理：

- Prisma CLI 包没有可直接 require 的主入口，最初 doctor 误判依赖缺失；改为检查真实 CLI 文件。
- Windows 在网络探测后立即 `process.exit()` 出现 libuv closing 断言；改为正常返回及设置 exitCode，让事件循环自然结束。重复启动实测退出 0。
- 初次工作副本的批处理 LF 行尾被 cmd 错误解析；转换为 CRLF 并以 `.gitattributes` 固定，重新执行通过。该次错误不是用户此前报告的问题。

为加载新的实例标识，核对旧服务属于本项目后短暂重启网页和 API，数据库未停止。最终主开发预览保持可访问，供负责人复验。

## 2 用户真实反馈与兴趣区切换修复

用户指出：点击主页四个兴趣栏时切换不够丝滑，像直接刷新，讨论板标识会重新从下方移动；主要功能没有明显问题。

修复前浏览器实际检查：文档导航次数仍为 1，并非整页重新加载；慢请求时旧帖子卡片被移除，选中标识也换成新的 DOM 元素。这与用户感受到的刷新感一致。

实际原因与处理：

1. 原先每个按钮有条件创建标识，通过跨父元素 layoutId 移动。改为筛选容器中唯一、常驻的标识，初次不播放入场动画，只沿 X 轴更新。
2. 查询切换时会用全块 loading 替换结果。现在只在相同浏览学校范围内保留上次数据，显示“暂显示上次结果”，降低不透明度并设置 inert；真实请求成功后更新内容，错误仍显示可重试状态。
3. 原先兴趣入口和讨论板按钮共用自动滚动。现在只有从上方入口进入且讨论板尚在下方时才平滑定位；在讨论板内切换保持滚动位置。
4. 点击已选且没有搜索 / 主题条件的分区不再产生无意义导航。减少动态模式下指示器直接到位。

没有将旧数据冒称为新分区，也没有用缓存越过学校筛选；核心功能仍访问真实 API。快速连续选择时旧请求可取消，最终显示最新选择。

关联文件：`Discover.tsx`、`styles.css`、`community.spec.ts`。真实反馈记录见 [体验表](../feedback/WEEK_01_TRIAL.md)。
