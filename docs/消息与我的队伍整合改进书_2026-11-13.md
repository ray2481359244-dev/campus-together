# 碰个头｜消息与我的队伍整合改进书

**审阅稿 v1.0 · 2026年11月13日**

建议把底部「消息」做成统一的聊天首页。私聊和队伍群在同一列表里，点队伍就进群。「我的队伍」保留为列表筛选，成员、公告、招募进度和管理从群名进入。用手机找群时，从底部导航到开聊只需两次点击。

本稿细化上一版的消息中心、群聊和通知方案，可用于下一轮实现与验收。 [11 月 3 日改进书](招募与社交消息改进详情书_2026-11-03.md)

## 1. 对照当前项目

| 现在的路径或能力 | 使用中要解决的问题 | 建议调整 |
| --- | --- | --- |
| 底部「消息」打开站内通知，评论、点赞、审核、队伍进展混排 | 看得到进展，找不到正在聊的队伍 | 默认打开聊天列表，把互动、申请和结果收进页顶「通知」 |
| 「我的」→「我的队伍」→队伍详情→群聊 | 只想说一句话也要经过两层队伍页面 | 「消息」→点队伍→聊天。「我的」原入口打开同一列表的「我的队伍」筛选 |
| 群聊先显示状态、公告、同步和已读按钮，再显示聊天 | 最近消息和输入框难找 | 群名、消息区和固定输入框形成主布局。公告只显示一行摘要 |
| 队伍详情已有成员、岗位、关闭招募、转交队长、开始和结束活动 | 合并入口时容易重新做一套管理页面 | 将现有详情和管理能力接入「群资料」，继续使用当前角色与状态校验 |
| 群聊已有数据库持久化、重复发送保护、历史分页与序号补取 | 断线可补取，但接收依赖页面定时同步，已读需要手动标记 | 先统一已读、补取与错误提示，再接实时变化提醒 |
| 申请、退队、移除和归档已有独立状态与通知 | 同一事件可能出现在队伍群和通知里，也可能改变会话访问权限 | 用真实成员资格驱动会话列表，明确每种状态的入口、历史与角标 |

对照依据是本地工作区的路由、消息页、队伍页和聊天接口。当前正式路径仍是上述结构。工作区已存在私聊与讨论群的契约、数据库迁移及实时事件代码草稿，当前应用路由尚未接通这些会话。本稿将它们作为后续接入点，预计效果留待实际验证。

## 3. 消息首页与原入口去向

消息首页只留一个标题、一个搜索框、三项筛选和一个「通知」按钮。默认筛选「全部」，显示有权限的会话。恢复上一会话由用户点开，打开消息首页时保留未读。

| 入口 | 打开后看到什么 | 点下一步会去哪里 |
| --- | --- | --- |
| 底部「消息」 | 全部会话，按置顶与最近活动排序 | 点队伍行进队伍群，点私聊行打开对应会话 |
| 首页「我的队伍」筛选 | 所有当前有效成员的队伍，含暂无聊天消息的队伍 | 点名称进群。已结束队伍由列表底部「已归档队伍」展开 |
| 首页「私聊」筛选 | 可打开的一对一会话 | 点会话开聊。陌生人首条请求在通知中处理 |
| 「我的」里的「我的队伍」 | 消息页直接选中「我的队伍」 | 和底部入口共享同一批会话与已读状态 |
| 页顶「通知」 | 「待处理」与「动态」 | 待处理含队长收到的申请、入群申请和新联系人。动态含评论、点赞、审批结果及系统通知 |
| 招募详情、批准结果、发布成功页 | 仍是有效成员时显示「进入队伍群」 | 直达同一会话。待审时显示「查看申请」 |
| 帖子评论的「私聊」与关联群 | 打开已有私聊、发起联系请求或查看讨论群 | 请求接受后归入会话列表。讨论群行显示「讨论群」 |

与上一稿的差异是将「互动」「通知」从首页并列标签收拢进页顶入口。消息首页以找人和找群为主。通知打开后默认优先显示「待处理」，空时显示「动态」。从具体通知跳到评论、申请或群聊后，返回时恢复原通知分组和滚动位置。

### 3.1 会话行怎样排

- 一行显示头像、名称、最近一条可见消息的摘要、时间和未读标记。私聊名称直接用对方昵称。队伍群在名称旁显示「队伍」，需要时显示「队长」「招募中」或「只读」。
- 置顶会话固定在上方，置顶区按置顶时间排序。其余会话按最近一条已保存且可见的聊天消息排序。空队伍以加入或创建时间定位，并显示「发条消息约个时间」。草稿和已读变化只更新对应行。轮询读到真实新消息时才更新该行的活动时间。切换筛选后仍是同一会话。
- 列表搜索按用户昵称、群名和队伍名检索已有会话。点结果直达会话。搜索覆盖分页后的全部可见会话，命中不了时提示「没有匹配的会话」，并保留筛选条件。
- 每行提供可发现的「更多」入口，含置顶、免打扰和标为已读。手机长按和电脑右键可作为快捷方式。菜单支持键盘操作并回到原触发点。
- 草稿按账号和会话保存。同一登录会话内切走再回来可继续编辑。列表用「草稿」提示，最近消息时间保持原值。退出登录后清除本次本地输入。

## 5. 群资料与队伍生命周期

进入队伍群就能看见群名和人数。群资料聚合当前可见公告、正式人数、岗位、我的角色和招募入口。普通成员可查看安排、成员和个人会话设置。队长还能审批、维护公告、转交队长、关闭招募及管理活动，沿用现有确认步骤和服务端事务。

| 事件 | 列表与通知 | 进入后 |
| --- | --- | --- |
| 自己发布、直接加入、申请获批 | 成功后同一队伍行出现。批准通知可直达聊天 | 状态变为正式成员，按队伍历史规则查看消息 |
| 申请待审、拒绝、撤回或失效 | 在申请或通知显示状态 | 可查看自己的结果。群入口在获得成员资格后出现 |
| 关闭招募或满员 | 队伍行继续显示，状态更新 | 现有成员照常聊天。队长管理入口按实际权限显示 |
| 活动开始 | 更新「进行中」 | 可继续发言和查看公告 |
| 完成、取消或到期 | 进入「已归档队伍」，保留仍有效的入口 | 群聊按当前政策只读。详情提示确切保留期限 |
| 归档期限结束 | 保留可见的队伍摘要和结束状态 | 历史、公告、最新消息摘要及搜索结果一并收起，仍可查看有权限的队伍资料 |
| 退出、被移除或账号失效 | 移出可读会话列表。相关结果通知仍按账号权限显示 | 正在打开的聊天收起，回到列表并说明状态。若后续具备重入资格，依服务端确认后恢复访问 |
| 仅加入帖子讨论群 | 在全部会话显示「讨论群」 | 只读取该讨论群允许查看的范围，正式队伍名额保持原值 |

当前项目队伍终态归档默认 30 天，可配置。改版时，列表摘要、历史、群资料、引用和搜索应共用同一权限与归档判定。用户关闭「群资料」后应回到群里，处理申请后仍能从消息页返回原筛选。

## 6. 消息怎么发、怎么收、怎么读

| 场景 | 建议行为 | 用户能看到什么 |
| --- | --- | --- |
| 发送一条消息 | 点击发送后立即显示临时气泡，后台保存成功后与正式消息合并 | 「发送中」随后显示正常时间。列表摘要在保存成功后更新 |
| 明确发送失败 | 保留正文和引用。允许重试或继续编辑 | 气泡旁显示「发送失败 · 重试」，错误原因靠近对应消息 |
| 提交超时，结果未知 | 使用原发送编号查询或重试，服务端识别同一次发送 | 「待确认 · 重试」，对方最终只收到一条 |
| 前台正看最新消息 | 新消息进入底部。窗口在前台、消息实际可见时推进已读位置 | 聊天仍留在底部，当前会话免于弹重复提示 |
| 正在翻旧消息 | 保持当前滚动位置，新消息累计在底部跳转提示 | 「有 3 条新消息」，点击后定位。未浏览的记录保留未读 |
| 刚打开有未读的会话 | 可加载到首条未读时，从「以下为新消息」处开始 | 一眼知道从哪里读。大量积压可手动「标为已读」 |
| 断网或切到后台后返回 | 恢复时重新核对权限，从上次收到的消息序号补取并去重 | 连接异常时才显示「正在重连」。已看到的历史保持原位置 |
| 多端登录 | 已读位置由服务端记录，并按会话单调推进。刷新会话同步摘要、设置与未读 | 手机读完，电脑角标随下一次同步更新 |

「已发送」表示服务端已保存。首期使用个人已读位置做未读数同步。向发送者公开的阅读回执可以后续按需设计。

### 6.1 未读和免打扰

- 行尾数字表示本会话未读消息条数，最多显示「99+」。自己的发送、历史分页和普通群状态条目不增加聊天未读。
- 底部「消息」数字建议表示**有未读的非静音会话数**。例如两个群分别有 5 条和 2 条未读，底部显示「2」，两行分别显示「5」和「2」。通知入口显示待处理数量，只有新动态时显示提示点。底部无聊天未读但有待处理事项时也使用一个提示点。
- 静音会话继续收取并显示摘要，行尾用静音图标和低强调未读点。申请待审核、移除或其他账号相关的重要进展仍在「通知」保留记录。群内 @ 提醒上线后，由用户决定免打扰是否为 @ 自己保留例外。
- 打开首页、筛选或看群资料时，未读保持原值。点击会话并实际看到新消息时才自动标记。只在连续已读范围内推进，跨过未看的区段需明确标为已读。已读写入合并发送，避免每条消息都请求一次。

### 6.2 通知怎么少而清楚

| 内容 | 落点 | 主要操作 |
| --- | --- | --- |
| 聊天正文、回复、后续 @ | 对应会话 | 回到消息位置继续聊 |
| 队长收到加入申请、新联系人或讨论群请求 | 通知 → 待处理 | 查看申请、接受、拒绝，处理后从待处理移除 |
| 自己申请获批、拒绝、失效 | 通知 → 动态 | 已获批的有效成员直接进群，其余查看自己的申请 |
| 评论、回复、点赞 | 通知 → 动态 | 定位原评论。连续点赞按帖子聚合 |
| 队伍开始、取消、归档 | 群内状态条及相关成员的结果通知 | 已在前台看群时使用轻量状态反馈，减少重复弹窗 |

「标为已读」只改变提醒状态。待处理事项完成后才退出待处理列表。发起人处理完一条申请，其他设备也应看到同样结果。陌生人请求保留一条文本和来源，接受后进入私聊。已拒绝、拉黑或关闭接收时按账号设置执行。

## 7. 聊天动作与主题动效

首屏常驻的是返回、群名或联系人名、群资料、输入和发送。公告有内容才显示，可点开看完整。消息的回复、复制、举报等收进单条消息菜单。键盘焦点、触屏和鼠标均可操作。电脑默认用 Enter 发送、Shift＋Enter 换行，中文输入法选字期间保留 Enter 的选字行为。手机保留明确的发送按钮。

| 交互 | 动效与状态 | 建议验收 |
| --- | --- | --- |
| 点发送、返回、更多、群资料 | 沿用「碰个头」轻压回弹。触摸和键盘也给反馈 | 立即响应，导航和发请求可在动效进行时开始 |
| 筛选与会话选中 | 浅紫选中底和标签指示平滑移动，保留可见焦点 | 快速连点可中断，最后一次选择对应实际内容 |
| 群资料与消息菜单 | 短距离展开，关掉后回到原触发点 | 背景滚动和输入草稿保持。Esc 与返回键有效 |
| 自己发送与新消息 | 临时气泡轻入场，保存回执只更新状态。接收时仅真正新增的记录短暂出现 | 断线补取多条时一次更新。旧历史、轮询和已读变化静态刷新 |
| 置顶、免打扰、申请处理 | 按下先反馈。请求完成后才变更图标、排序或显示结果 | 失败时保留真实状态，并给出重试 |
| 搜索、输入、上传等后续动作 | 聚焦时清楚描边，保留文本选区。请求与进度用文字和轻量反馈 | 关闭动效或系统要求减少动态效果时，仍能看清焦点、状态和进度 |

建议按钮回弹约 180—260 毫秒，聊天气泡约 120—180 毫秒。群资料在较宽屏幕用侧栏，小屏用抽屉。动效优先在位置、透明度和按钮按压上表达变化，聊天滚动保持稳定。整站仍用现有动效偏好控制。

## 8. 实现顺序与项目衔接

| 优先级 | 交付范围 | 可核对的完成条件 |
| --- | --- | --- |
| P0 · 统一入口 | 消息列表、我的队伍筛选、手机单列和电脑双栏、群资料、通知入口、旧链接承接 | 发布或入队后自动出现队伍行。有效成员点一行即可聊天，管理动作仍可执行 |
| P0 · 可靠收发 | 序号补取、已读、草稿、置顶、免打扰、即时更新、失权处理和动效 | 两个账号互发、断线重连、重复发送、退出和归档均通过测试 |
| P0 · 私聊接入 | 接上上一轮的评论私聊与联系人请求，进入同一个会话列表 | 已有会话可复用，首条请求可处理，聊天与通知角标各自正确 |
| P1 · 常用聊天能力 | 引用回复、群内 @、本群历史搜索、图片、分享帖子或招募、讨论群接入 | 只有当前有权限的用户能看到对应内容。讨论群与正式队伍身份清楚 |
| P2 · 进阶沟通 | 跨会话历史搜索、文件、快捷回复、活动提醒、网页后台推送评估 | 根据真实试用确定先做哪项。系统推送需单独验证浏览器支持和权限 |

私聊可以在队伍列表先验收后接入。首期最终验收时，私聊和队伍群须在「全部」列表同时可用。桌面和手机使用同一会话标识与接口。

### 8.1 可直接复用的代码

现有队伍聊天继续使用队伍成员身份、消息序号、重复发送保护和归档策略。统一列表把队伍群、私聊和讨论群映射到一套行数据。每行带会话类型与标识、标题、最近可见消息、活动时间、未读、置顶、静音和访问状态。队伍群权限仍从正式成员记录判断，私聊和讨论群使用各自成员与请求状态。

当前「我的队伍」和队伍详情已读到成员、角色与活动状态。前端可以将这两处的列表与管理组件接入消息页。聊天中的队伍资料在打开时再读取。列表摘要批量返回，避免每个队伍先打开一次聊天接口才能得到最新消息。分页、搜索和未读汇总均按账号及权限计算。

### 8.2 更新、回退与兼容

- 建议由已授权的长连接发送轻量变更提醒，再走当前的受权限保护读取接口获取消息。序号补取仍负责重连恢复。工作区中的事件流代码可作为接入起点，需确认路由、身份校验、跨标签页、代理连接和降级轮询后再启用。
- 列表刷新和当前会话补取要合并，防止多条提醒触发重复请求。轮询作为降级路径，可见页面缩短同步间隔，后台降低频率。退出、移除和归档后重新校验列表、摘要与打开的聊天。
- 旧「我的队伍」入口落到消息页的「我的队伍」筛选。旧群链接跳到同一会话。旧队伍详情可进入群资料。旧通知链接跳转保留目标和返回路径。
- 先在独立演示库验证迁移和两个账号的历史。需要更新会话数据时保持原队伍标识与已读序号。新版入口可先用项目配置逐步启用，恢复旧入口时同一批消息仍可读取。

## 9. 建议试用和回归

| 任务 | 可接受的结果 |
| --- | --- |
| 在手机上打开「消息」找一支已加入队伍 | 从底部入口起两次点击进群。队伍还没人发言时也找得到 |
| 电脑同时看私聊和队伍群 | 左栏切换，右栏换会话。输入到一半切走再回来，原稿仍在 |
| 队长审一个申请 | 从「通知」或「群资料」看申请。批准后申请者出现队伍行，已处理项从待处理消失 |
| 同时给两支队伍发消息，静音其中一支 | 两行摘要和未读按规则更新。底部只统计未静音的未读会话 |
| 一方翻历史时对方连续发三条 | 历史位置稳定，显示新消息入口。定位后条目和数量一致 |
| 发送后模拟响应丢失并重试 | 同一消息只保存和显示一次 |
| 断网后恢复，同时让手机和电脑打开同一群 | 漏掉的消息按序补齐。旧设备的已读写入不能使新读过的消息变回未读 |
| 从旧队伍链接、批准通知和帖子评论分别跳转 | 均打开正确位置，返回恢复原页面与筛选 |
| 账号退队、被移除、归档到期 | 对应历史、摘要、搜索与输入权限一致。其他有效成员仍按规则使用 |
| 手机 320 像素宽、中文输入法、键盘和减少动态效果 | 文本可换行、发送可触达、选字时不误发。关闭动效时状态与焦点仍清楚 |

试用时建议让 6—8 位同学分别用手机和电脑完成找群、回复和处理通知。记录点击次数、是否误进队伍详情、是否误解未读与静音、发送或重连是否需要手动操作。健康本地环境可把「保存成功至另一前台客户端显示」的第 95 百分位 2 秒内作为初始目标，记录浏览器、延迟和测试轮数。以上是目标，验收结果按实测填写。

## 10. 需要审阅的产品选择

| 议题 | 本稿建议 | 可调整之处 |
| --- | --- | --- |
| 「我的队伍」放哪 | 作为「消息」的醒目筛选，个人页提供同一路径 | 试用中若经常被忽略，可放在搜索框下固定位置 |
| 点击队伍先看什么 | 进入聊天。点群名看资料 | 队长可从行尾菜单直接打开待审 |
| 归档放哪 | 折叠到队伍列表底部，保留到期状态 | 可按试用反馈增加独立的「已归档」筛选 |
| 通知是否常驻在聊天页 | 列表页顶一个入口，内有待处理和动态 | 电脑可在保留会话列表时开通知面板，手机用独立视图 |
| 先做到 QQ 的哪些能力 | 统一会话、可控提醒、清晰未读、易找群和可靠同步 | 语音、文件和推送按使用数据决定顺序 |
