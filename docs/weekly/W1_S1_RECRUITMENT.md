# W1-S1 最小竞赛招募：体验与验收

日期：2026-10-16。对应首周挑战任务，沿用每周 30—40 小时滚动计划。不是完整第二周组队验收。

## 现在可以做什么

在本地平台打开「招募」，进入竞赛招募大厅。内容来自 PostgreSQL；测试使用专用测试库，不会把自动化用的招募塞入你的账号。

1. 用自己的账号点击「发起竞赛招募」，先只填标题，点击「保存私有草稿」。收到保存提示后刷新，内容应仍在。
2. 返回大厅，展开「我的私有草稿」继续编辑；另一个账号访问草稿链接应看到不存在 / 尚未公开。删除草稿需要再次确认。
3. 补齐竞赛主题、标题（5—60 字）、说明（20—3000 字）、比赛名称、项目方向、本次目标和协作时段。官方链接与已有技能可选，技能仅为自述。
4. 按北京时间填写开始、结束与比赛截止。招募截止可留空，默认采用开始时间；发布时必须仍在未来，截止不能晚于开始，结束必须晚于开始。线下协作另填公开集合区域。
5. 核对总人数与岗位。默认总人数 3：项目统筹 1、开发伙伴 2；队长占项目统筹一个名额，发布后显示 1 / 3，不能把队长另加在总人数外。每人只占一个岗位。
6. 点击「预览并发布」，核对公开内容，再点击「确认发布招募」。成功后进入真实详情；刷新和其他账号读取都应显示相同岗位人数。
7. 也可以打开自己在竞赛区发布的讨论，点击「从讨论发起招募」。标题、正文和主题会预填，并保留来源关联。讨论与招募分别保存；删除来源讨论不删除招募，来源位置显示不可用。

如请求失败，当前输入保留。只有收到明确保存 / 发布成功才算完成；若发布已落库但成功响应丢失，再次确认可返回原队伍，不重复建队。草稿是手动保存，关闭前尚未保存的修改没有持久化保证。

10 月 19 日 W1-06 联调补充：首次读取草稿或来源讨论失败可重试，已开始编辑后的后台失败内联显示且保留表单；重新读取较新版本不替换本地输入或 revision。草稿在另一页发布 / 删除后，本页保留输入并停止写入。详见 [集成与恢复步骤](W1_06_INTEGRATION_REVIEW.md)，原样写入重试与未确认结果后修改内容的情况分别处理，后者仍待专项验收。

## 自动验收覆盖

| 风险 / 行为 | 实际检查 |
| --- | --- |
| 私有草稿越权 | 作者可读改删；其他账号与匿名读取 404；草稿不出现在公开列表 |
| 重复请求 | 同键同内容并发创建只生成一份；同键不同内容 409；并发发布只建一队 |
| 人数和引用 | 岗位合计、队长选择、有效竞赛主题、当前学校与自己的来源讨论检查 |
| 原子发布 | 队伍、岗位、队长、聊天空间元数据、事件和公开状态同事务 |
| 真正回滚 | 仅在测试库创建临时触发器，让聊天空间写入报错，确认之前子项不残留；finally 移除触发器，随后可正常发布 |
| 前端失败恢复 | 保存 503 时保留输入并重试；发布已提交后模拟响应丢失，再次点击返回原详情 |
| 来源删除 | 原讨论不可读，招募内容和队伍仍存在，页面展示来源不可用 |
| 布局与回归 | 320px 表单不横溢、390px 详情、1440px 另一账号；原账号 / 讨论 / 四区 / 手势测试仍通过 |

验证命令与最终结果见 [当日日志](../development/2026-10-16.md)。截图仅含测试虚构账号，保存在忽略的 `.local/screenshots`；没有将负责人账号截图或邮箱上传。

## 当前阶段边界

- 只开放竞赛区，暂仅 APPROVAL 模式的发布；申请、批准、直接入队、成员变更、队长转交和完整生命周期未接入。
- 已发布招募只读；草稿可编辑删除。发布前请核对信息，发布后修改 / 取消将在队伍规则阶段实现。
- 聊天空间只建立实际数据库关联，不支持收发消息；事件落库不等于站内通知或推送完成。
- 游戏 / 学习 / 户外招募、PASS / FAIL / UNKNOWN、AI 草稿、图片评论、举报管理仍是后续工作。
- 账号、学校和技能未做实际核验；没有公网演示站。此轮未做新增招募的 PostgreSQL 重启或备份恢复检查。
