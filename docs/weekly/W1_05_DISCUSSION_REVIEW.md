## 怎样体验发布失败恢复

1. 登录后在“发布”填写主题、标题和正文，正常成功后进入详情，可继续编辑。
2. 网络错误使发布结果未知时，输入仍在且暂时锁定；点击“核对并完成发布”安全重试同一次提交。先前已成功就进入原帖，尚未保存则完成一次创建。
3. 若主题已停用，服务端明确拒绝后可修改输入或重新选主题。普通超时、503、限流或网关错误不能证明先前未保存，继续保留同次提交。
4. 不要用关闭 / 刷新页面来核对结果：当前没有未提交内容自动备份，跨页面后应先查看讨论板。账号切换继续适用既有身份清理规则。

浏览器自动化在测试库真实保存后主动丢弃成功响应，接着模拟网关非 JSON 400，再安全重试。也覆盖保存前 503、真实不存在主题的 422 与修正后的发布。复现脚本不是界面提供的断网开关，正常体验不必故意破坏网络。

## 怎样体验双标签页编辑

1. 在 [本地平台](http://127.0.0.1:5173/discover)登录自己的账号，创建一条测试讨论，进入“编辑讨论”。
2. 同一个浏览器开另一标签页，使用相同账号编辑同一讨论。两页分别写不同标题，在第二页先保存。
3. 回到第一页，点击“核对已保存版本”。服务器版本会单独展示；下方尚未保存的输入不应变动。页面重新获得焦点后的后台读取同样不应覆盖输入。
4. 第一页仍基于旧版保存时应提示冲突，不能覆盖第二页已保存内容。保存按钮会停止重复冲突提交。
5. 如需改用新版，点击“用此版本重新编辑”。可以选择“继续保留我的输入”；只有“确认载入已保存版本”才替换下方内容并更新编辑基准。合并所需文字请先手动复制，系统没有自动合并。
6. 原讨论在另一页删除后，再核对应提示不存在，但本地未保存的正文仍在。首次打开已删除链接则正常显示不可见错误。

普通编辑保存失败保留当前内容，可检查网络后重试。若编辑请求可能已经提交但响应丢失，应核对服务器版本；不能据错误判断原请求未生效。创建重试已在 10 月 19 日补齐，适用上面的发布恢复步骤；编辑 PATCH 仍由 revision 拒绝旧版本覆盖。

账号在另一标签页注销 / 切换时仍适用既有身份恢复规则，会清除旧账号缓存与未提交表单，防止内容转移到新账号；不与同账号普通读取失败混为一谈。关闭或刷新整页没有自动备份保证。
