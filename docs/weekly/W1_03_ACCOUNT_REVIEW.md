# W1-03 账号、资料与会话体验

日期：2026-10-17。当前代码 `f528ded`，对应首周第 3 天。基础账号功能原已完成，本轮补齐失败与并发边界。

## 可以按这条路径检查

1. 打开本地平台，注册并进入「我的」，修改简介、技能与兴趣，保存后刷新，应保持已保存内容。
2. 两个独立浏览器上下文可同时使用不同账号；同一浏览器的普通标签页共用登录 Cookie，不能把两个普通标签页当作两个独立账号环境。
3. 在同一浏览器打开两个平台标签页。一个页面填写内容但不提交；另一个页面退出或换账号，原页面应提示「登录状态已变化」，停止旧账号操作。
4. 点击「重新加载并确认账号」，明确当前登录者后继续。**身份变化会清除旧页面缓存和未提交表单**，不会自动把原内容转交给新账号；已经保存到数据库的草稿仍在原账号下。
5. 普通保存网络失败的处理不同：错误提示可重试，当前输入保留。登录状态本身读取失败时显示重试入口，不直接认定为未登录。

需要退出或切换账号前，请先保存仍需继续的草稿。这不是自动草稿备份功能，不能把尚未保存的输入当作已经落库。

## 技术验收

| 场景 | 实际结果 |
| --- | --- |
| 注册时会话表写入失败 | 用户 / 资料 / 会话及旧上下文撤销同事务回滚，不留下孤立账号；去除测试故障后同邮箱可正常注册 |
| 旧页面用新账号 Cookie 发请求 | 服务端核对预期账号，拒绝私有读取 / 写入，不以新账号发布旧表单 |
| 服务端会话到期 | 原 Cookie 无法继续访问本人资料，独立账号不受影响 |
| 既有账号状态改为 SUSPENDED | HTTP 会话撤销、登录拒绝、公开资料不可读；没有增加管理后台或 Socket 功能 |
| 同一旧会话的并发登录 | 只有一个成功轮换，另一个被拒绝；不存在两个新的有效替代会话 |
| 并发登录和注销 | 只有一个成功争用旧上下文；失败响应不覆盖 Cookie |
| 跨标签页切换 / 注销 | 收到状态通知的标签页停止旧操作；独立上下文不受影响 |
| 不支持跨页通知 | 下一次账号相关请求仍由服务端拦截身份不一致，不偷偷重试为新账号 |
| 同账号 CSRF 更新 | 保留原请求的身份与会话版本，自动重试后正常保存 |
| 退出后迟到的失败 / 成功 | 旧请求结果不改变当前认证状态，不用旧资料响应恢复已注销用户 |

## 边界

跨标签页提示使用可选的 BroadcastChannel，只传状态事件。通知不可用时，不承诺即时感知另一页变化，但服务端检查在下一次账号相关请求仍生效。已经在旧会话下合法提交的数据库操作不会因随后注销而自动回滚；本轮保证迟到响应不覆盖当前页面状态。

账号一致性头不是身份凭据，Cookie / CSRF / Origin / 作者权限仍是服务端依据。清理页面状态不代表能够抹除他人已经看到、复制或截图的历史内容。

邮件验证、密码找回、管理封禁界面、Socket 撤权、自动备份未提交输入仍未实现。初访 / 同学试用和干净新机器验证未在本轮完成。10 月 21 日照常进行周复盘。
