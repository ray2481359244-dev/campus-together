## 失败尝试与实际修复

1. 首次调用工具附带的 pnpm 11.25.0，项目要求 11.5.1，离线自动切换缺少 `@pnpm/exe@11.5.1`。安装失败，不能计为成功。改用本机实际安装的 pnpm 11.5.1 后锁文件安装通过。
2. 第二次安装和数据库完成，但直接打开 `/register` 失败。复查结果：首页 200、ready 200，注册深链接返回 503。原因是隐藏父目录 `.local` 被绝对路径 `sendFile` 的默认路径检查影响。
3. 将 SPA 回退改为 `res.sendFile('index.html', { root: web })`，把静态根目录边界显式交给 Express。没有关闭 dotfiles 保护，也没有将 API 错误变成首页。
4. 新增 `test:serve`：在专用隐藏父目录验证 `/`、`/register`、`/posts/example` 返回 HTML，未知 API 仍返回 JSON 404。检查通过后提交 `b611855`，重新从新目录执行整条复现链并通过。

首次、第二次的失败结果保存在本地 `.local/reproduction-day2-attempt1.json`、`attempt2.json`，不倒填为成功。截图和隔离数据留在忽略目录，不上传个人运行材料。

## 按同样步骤复查

先确认 Node 24 与 `pnpm --version` 为 11.5.1。安装好所需工具并选择空目录：

```powershell
git clone https://github.com/ray2481359244-dev/campus-together.git campus-reproduction
Set-Location campus-reproduction
git checkout b611855
pnpm.cmd install --frozen-lockfile
pnpm.cmd setup
```

本次实测的克隆源是本地仓库；上述 GitHub 克隆路径供他人复查，下载时间并未包含在本次计时内。已有完整缓存时可增加 `--offline --store-dir <实际缓存目录>`，无缓存不使用离线参数。

若同机已有主平台，请在新目录 `.env` 将两条数据库 URL 的端口改为 5433，`LOCAL_PG_PORT=5433`、`PORT=3104`、`WEB_ORIGIN=http://127.0.0.1:3104`，先确认端口空闲；不要改主项目环境，也不要把 .env 内容粘贴到聊天或仓库。

```powershell
pnpm.cmd db:local
```

保留数据库终端，在独立目录的另一终端执行：

```powershell
pnpm.cmd db:generate
pnpm.cmd db:migrate
pnpm.cmd db:seed
pnpm.cmd build
pnpm.cmd start
```

打开 `http://127.0.0.1:3104/register`，注册虚构测试账号、发布讨论、刷新确认保留。此为构建产物同域模式；日常开发的 `pnpm local` / doctor 固定检查 5173，不能混同为这一隔离构建模式。

结束时正常停止该次服务，在独立目录执行 `pnpm db:stop`，不停止主项目的数据库。干净机器验证时还需记录操作系统、下载网络、工具安装、依赖与数据库初始化和总耗时。
